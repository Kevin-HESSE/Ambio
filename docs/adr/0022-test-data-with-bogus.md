# 0022 — Test data built with Bogus

- Status: Accepted
- Date: 2026-10-13

## Context

The first slices (companies, offers) wrote their test data by hand: each test class declared its DTOs, entities and form inputs field by field, with constants such as `Brightwave`, `Lyon` or `https://brightwave.io`. The same objects were retyped in several classes, a new field meant editing every one of them, and a reader couldn't tell which values a test relied on from those that only filled the object. The next slices (applications, statuses, cover letters) bring many more entities.

## Decision

- Web and Infrastructure tests build their data with **Bogus**, through one generator per type in `Fixtures/` (`GetGenerator()` returns a `Faker<T>` that fills every field). Domain and Application tests check rules on a few values and keep them literal. E2E journeys type their values in the UI and keep them readable.
- Values are **random on every run, without a seed**. A test sets, with `with` or a `WithCustom…` extension, only the values it checks or relies on (a name whose case or slug is checked, a sort order, a displayed date), and reads every other expected value from the generated object.
- Variants are **rule sets** exposed as constants that include the default rules (`"default,archived"`).
- Entities that depend on another one are generated by **stories** (`JobOfferStory`: a company, its offers and their postings), created per test and saved in order.

## Consequences

- A test shows what it depends on: the overridden fields. Adding a field to an entity or a DTO only changes its generator.
- Random data can reveal a hidden dependency, such as an assertion that only held for one value. It can also fail by chance: names and slugs are unique in the database, so a test that needs two distinct companies gives one of them a fixed name that Bogus can't produce.
- A failure isn't replayed with the same data. The assertion message shows the values involved; a seed can be set on a generator (`UseSeed`) while investigating.
- Bogus is a test-only dependency, declared in `Directory.Packages.props` and referenced by the Web and Infrastructure test projects.
